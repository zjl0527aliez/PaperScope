# PaperScope v0.7.4 验收计划

## 目标

v0.7.4 在 v0.7.3 的材料边界与安全归档基础上，重点解决两件事：显著数值必须可追溯，质量提升必须能与 Token 和耗时增量对应。

## 已实现

1. 百分比、模型规模、小数和两位以上显著数值必须出现在对应阶段的摘要、正文或相关论文材料中。
2. 相关工作摘要按各自材料独立校验，避免一篇论文的数值被错误借给另一篇。
3. 每次模型请求记录阶段名、结构修复轮次、传输尝试数、Token 和耗时；缓存阶段显示为 0 新 Token、0 模型耗时。
4. 汇总 DeepSeek `prompt_cache_hit_tokens`、`prompt_cache_miss_tokens` 与 reasoning token（供应商返回时）。
5. ReASC 评测拆分材料准备、研究请求、服务端和模型阶段耗时；摘要/全文 Markdown 对比直接展示质量与成本变化。
6. 最近运行安全归档同步保留模型耗时和 Prompt Cache Token 摘要，不保存 API Key、Authorization、密码、原始全文或 `sourceText`。
7. 语义相关论文不得被表述为种子论文的思想来源、继承、延伸或后续工作；成对评测记录执行顺序与 OpenAlex 缓存状态。

## 统一测试

完成 DeepSeek 配置后运行：

```bash
python3 scripts/benchmark.py pair --label v0.7.4-deepseek
python3 scripts/benchmark.py pair --label v0.7.4-deepseek-reverse --order fulltext-first
```

建议再运行三次稳定性评测：

```bash
python3 scripts/benchmark.py repeat --label v0.7.4-deepseek-abstract --runs 3 --material abstract
python3 scripts/benchmark.py repeat --label v0.7.4-deepseek-fulltext --runs 3 --material auto-oa
```

## 验收条件

- 摘要版与自动全文版均成功，且材料范围标记正确。
- 自动全文版包含 `seed-evidence`，六个 ReASC 事实锚点全部命中。
- 报告中的百分比、模型规模和其他显著数字可在对应来源材料找到。
- 不出现自创方法译名或无边界的“不依赖/不使用”判断。
- `schemaFallbackCount` 目标为 0；发生降级时逐项人工确认。
- 对比报告同时给出总 Token、Prompt Cache Token、模型阶段耗时、服务端耗时和端到端耗时。
- 全文版的额外成本必须带来事实锚点、实验设置、发现或精读价值，而非仅增加篇幅。
